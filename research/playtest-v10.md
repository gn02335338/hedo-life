# e10 玩家試玩與節奏修正

2026-10-20。這次保留 e9 的升遷難度，處理重複通知與手機操作的疲乏。沒有新增結局，也沒有放寬高階能力、任期或成功判定。

### 流程檢查

1. **選職缺、骰履歷、報到：正常。** 改派與未改派都實際遇到，職稱和薪水清楚，選前未顯示數值效果。
2. **日常選擇、揭曉結果、繼續：修正後順暢。** 手機原本每回合回到完整工作證，新故事在約 800px 以下；現在直接定位新故事或結果，故事上方可看重要資源並往返工作證。
3. **升遷、準備與婉拒：修正後減少打斷。** 未具備申請條件時不強制叫去評核，改由玩家按工作證主動準備；婉拒延長等待期。能力、任期及高階難度維持 e9。
4. **PIP、留下與後續工作：修正後可持續推進。** 同一段低心情只啟動一次人事爭議；正常工作讓老闆心情恢復後，未來再次惡化仍可觸發新爭議。PIP 通過不補老闆心情。
5. **中後期與離場：檢查通過。** 實際遇到降薪協商、不同工作事件及提前離場；尾段完整 PIP 與 234 種結局由自然路線及 API 測試補查，沒有宣稱四輪介面試玩走完全部結局。
6. **窄螢幕與圖鑑：修正後正常。** 360px 首頁裝飾圖原本撐寬到 401px，已限制裝飾的水平溢位；工作證操作鈕至少 44px 高。鍵盤跳至主要內容、圖鑑關閉及未解鎖問號已確認。

手機是 Chromium 尺寸模擬，並非實體 iPhone／Android。此次未完整驗證螢幕閱讀器、真機軟鍵盤、所有動態字級或 WCAG 符合性。截圖與逐步選擇保存在本機忽略的測試資料夾，不公開私人瀏覽器資料。

這些是策略情境，不是玩家人口比例。e9／e10 前綴會改變初始亂數，同尾碼不代表完全相同的人設；7 與 8 個 C-level 樣本的差別不能解讀為新版較容易升職。

## 規則與相容性

- e10 自動評核需要可申請的選項；主動準備只在工作中的合法時點開啟，不耗工作日或額外亂數。訓練／婉拒仍受等待期限制。
- 同一個持續低老闆心情階段只進一次人事危機。非 PIP 的實際工作回合讓老闆心情達 35 後才重新允許下一波危機；原本的六工作回合緩衝仍保留。
- 尾段只在足夠完成三個工作回合時提供新 PIP；到期評核會先於最終職涯結算完成。
- 新局使用 `e10-`。舊局、匿名身分、收藏及離線待同步紀錄保持原格式；舊 e9 的 234 條路線與每個狀態均與修改前一致。
- 95 項測試、234 條 e10 自然結局路線、靜態建置檢查與本機 Wrangler／SQLite API smoke 通過。API 也驗證合法主動準備與偽造、重複或舊版使用該操作的拒絕行為。
